# エージェント間の合意：advisory と enforced の比較実験（2026年10月）

LLM エージェント同士が「共有の選択」（どれも正しいが、両立しない選択肢）に合意するための道具と、その実験コードです。
10/29 の研究ミーティングで報告した予備実験に対応しています。実験のログと結果のファイルは含めていません。

## フォルダの構成

| フォルダ | 中身 |
|---|---|
| `prototype/` | 合意の道具の試作品。手順書（`SKILL.md`）、合意ツール（`agree.py`）、hook の雛形、データ分析のデモ |
| `exp1_data_analysis/` | 実験1：データ分析タスクの予備実験。全条件が成功し、差が出なかった（天井効果） |
| `exp2_coding/` | 実験2（主な実験）：2人のエージェントが `pricing.py` と `invoice.py` を分担するコーディングタスク |

## 合意ツール `agree.py`

複数のエージェントが共有する1つのファイル（決定ログ、JSONL・追記のみ）に、提案・投票・確定を記録します。

| コマンド | 内容 |
|---|---|
| `init --participants a1,a2` | 合意に参加するエージェントを決める |
| `propose TOPIC VALUE` | 話題 TOPIC に値を提案する（新しい版を開く） |
| `respond TOPIC accept\|object` | 提案に賛成または反対する |
| `commit TOPIC` | 全員が賛成なら確定する。反対が1つでもあれば中止する |
| `lookup TOPIC` | 最後に確定した値を読む |
| `status` | 全話題の状態と、ログの改ざんの有無を表示する |
| `checker` / `check` | 出力が決定に従っているか（Conformance）を調べるコマンドを登録・実行する |
| `deviate TOPIC --why` | 決定に従えないことを宣言する |

ログはファイルロックで同時書き込みから守り、各行に前の行のハッシュを入れて改ざんを検出できるようにしています。

既知の限界：
- 話題の名前が自由なので、同じ選択を別の名前で提案されると防げない
- `propose` は「提案中のものがあるか」をロックの外で確認しているため、同時に提案すると両方通る可能性がある

## 実験2の条件

`exp2_coding/run_trial.py CONDITION REP [--model haiku]`

| 条件 | 内容 |
|---|---|
| `base` | メッセージ板のみ |
| `tool` | 合意ツールがあることだけ伝える（手順なし） |
| `inline` | 合意の手順をプロンプトに直接書く |
| `skill` | 同じ手順をスキル（`SKILL.md`）として渡す |
| `gate` | hook：合意が確定するまで担当ファイルに書き込めない |
| `ci` | hook：終了時に2人のコードを組み合わせて例題を実行し、失敗なら終了させない |
| `ci_barrier` | hook：2人が同じ版で準備でき、例題が通るまで、どちらも終了できない |
| `skill_ci` | `skill` と `ci` の両方 |

## 実行に必要なもの

- Python 3
- Claude Code（`claude -p` の非対話モードで2体のエージェントを起動する）
- 隠しテストは `exp2_coding/eval/` にあります。採点は `evaluate.py`、失敗の分類は `classify.py` で行います

`run_v2.sh` は8条件×10回をまとめて実行するスクリプトです。実行すると Claude の利用枠を消費します。
